# Безпека та подальша перевірка

Перевіряти потрібно окремо код, вебзастосунок, саму Pi та її доступність з різних мереж. Відсутність знахідок одного сканера не доводить захищеність усієї системи.

## Захист у 3.7.2

| Знахідка 3.5.1 | Захист 3.7.2 |
|---|---|
| Виконання HTML/JavaScript через audio.days | Дозволений перелік днів і не більше 7 значень; екранування також старих записів; CSP без unsafe-inline для скриптів і без unsafe-eval |
| Відомі ключі, перезапис власних ключів інсталятором | Випадкові ключі, міграція відомих стандартних значень, збереження власних ключів |
| Ключі в localStorage | Двогодинні серверні сесії, HttpOnly/SameSite, Secure через HTTPS, вихід, відкликання після ротації |
| Підміна екранів і підтвердження чужих команд | Окремий токен кожного екрана, перевипуск, адмінське підключення; локальний bootstrap не проходить через nginx |
| Незашифрований мережевий вхід | nginx/TLS 1.2–1.3 на 443; backend на loopback |
| Повільні запити й необмежені потоки | 24 обробники, таймаут бездіяльності 8 секунд, загальний час заголовків 10 секунд, звичайного запиту 25 секунд, медіа/завантаження 300 секунд; rate limiting |
| Безмежне накопичення завантажень | Квота 2 ГіБ, резерв 256 МіБ, серіалізація квоти й запису між процесами, перевірка сигнатур форматів |
| Root виконує змінюваний код програми | Root-owned watchdog у /usr/local/lib/lyceumtv, який не запускає Python/скрипти програми; окремі користувачі сервера та kiosk |
| Налагоджувальний браузерний порт доступний іншим локальним процесам | WebKitGTK не відкриває DevTools-порт; host/launcher встановлюються root-owned поза деревом застосунку |
| Хеш OTA без підтвердження автора | Ed25519-підпис маніфесту з незалежним root-owned ключем довіри |

Власні старі короткі ключі зберігаються для контрольованої міграції: замініть їх у панелі на випадкові значення щонайменше з 24 символів. Адміністративні API також підтримують ключі в заголовках для CLI-інтеграцій; використовуйте лише HTTPS. Публічне читання розкладу/TV залишається доступним за призначенням.

Перевірка сигнатури медіафайлу не є повним декодуванням, антивірусом чи гарантією безпеки кодека. Завантажуйте файли з довірених джерел і оновлюйте WebKitGTK/ОС. Спільний ключ ролі не дає персонального обліку людей; для ширшого використання наступним кроком мають бути індивідуальні облікові записи, відкликання доступу та MFA для адміністратора.

## 1. Власні регресійні тести

```bash
.venv/bin/python VERIFY_PROJECT.py
.venv/bin/python tests/browser_safety.py
.venv/bin/python tests/browser_security.py --nginx /usr/sbin/nginx
```

Сценарії працюють лише на тимчасових копіях і 127.0.0.1: без робочої Pi. Перевіряються ролі, старі ключі, ротація, закриті heartbeat/ack, область токена пристрою, CSRF, cookie, таймаути, квота, підпис і його підміна, справжні браузерні панелі та nginx/TLS. Без nginx відповідний сценарій позначається SKIP. Тимчасові TLS-ключі тестів не потрапляють у реліз.

## 2. Код і залежності

В окремому середовищі розробника:

```bash
python -m pip install bandit pip-audit
pip-audit -r requirements.txt
bandit -r server launcher.py
```

Повторюйте після змін і перед релізом. Попередження Bandit потребують ручної перевірки: сам виклик extractall або urlopen ще не означає, що перевірок перед ним немає. На Pi Python-пакети встановлюються через apt, тому їхні фактичні версії треба перевіряти окремо. Результат pip-audit для requirements.txt не покриває WebKitGTK, Python, OpenSSH чи nginx ОС.

## 3. Перевірка встановленої Pi через SSH

```powershell
.\CHECK_SECURITY_ORANGEPI.ps1
```

Або після входу через SSH, підставивши фактичну IPv4 замість `IP_ORANGE_PI`:

```bash
sudo /usr/local/sbin/lyceumtv-security-audit IP_ORANGE_PI
```

Перевірка читає відкриті порти, UID сервісів, права привілейованих скриптів і конфігурації, TLS-ідентичність/строк дії, відмову анонімному адміністратору, SSH-політику й firewall. Секрети не виводить. Порожній firewall, доступність SSH з учнівської мережі чи непотрібні порти потребують окремого рішення адміністратора мережі.

Для ширшого аудиту ОС на своїй Pi можна встановити Lynis та виконати:

```bash
sudo apt-get install lynis
sudo lynis audit system --quick
```

Це дає рекомендації для ОС, а не перевірку бізнес-логіки LyceumTV. Оновлення ОС/WebKitGTK виконуйте в запланований час із резервною копією. Не вимикайте пароль SSH, доки не перевірили вхід ключем у другому сеансі.

## 4. Перевірка з іншого комп'ютера

Якщо встановлено Nmap, проскануйте лише свою Pi:

```bash
nmap -sV --open -p 22,80,443,8080,9222 IP_ORANGE_PI
```

443 має бути доступним; 8080 і 9222 — закритими з іншого комп'ютера. 22 залежить від правил обслуговування. 80 може залишатися відкритим через іншу конфігурацію nginx/інший сервіс; цей проєкт не видаляє чужі nginx-сайти. З'ясуйте його призначення або закрийте, якщо він не потрібен. Nmap не замінює сканер веблогіки.

Повторіть перевірку з учнівського Wi-Fi: керування не повинно бути доступним із недовіреної мережі. Доступність із інтернету перевіряйте з зовнішньої мережі та за правилами маршрутизатора/переадресації портів. Локальний скан не показує всі зовнішні шляхи доступу. Для віддаленого адміністрування використовуйте VPN, а не відкриття панелі всьому інтернету.

## 5. OWASP ZAP

Встановіть ZAP на комп'ютері, налаштуйте довіру до CA Pi й почніть із пасивного сканування під час звичайного перегляду TV, /admin, /ops і /teacher. Окремими профілями перевірте анонімний доступ і кожну роль. Перевірте відсутність ключів у localStorage, прапорці cookie, заголовки та відмови на заборонені API.

Активне сканування, перебір параметрів, фаззинг і навантаження запускайте на тестовій копії з демонстраційними даними: вони можуть створювати/видаляти записи, впливати на звук або затримувати відображення тривоги. У хмарній перевірці 3.7.1 активний ZAP/фаззинг та навантаження фізичної Pi не виконувалися.

## Підписані OTA-оновлення

Повний SSH-інсталятор не потребує налаштування OTA. Без окремого ключа довіри OTA відхиляє пакети.

На окремому довіреному комп'ютері з OpenSSL створіть ключ релізів **поза проєктом/папкою збирання**:

```bash
openssl genpkey -algorithm ED25519 -out release-private.pem
openssl pkey -in release-private.pem -pubout -out release-public.pem
```

Приватний ключ зберігайте окремо від репозиторію й Pi. Додайте до приватних/CI-секретів, якщо налаштовуєте підписування через CI. Скопіюйте **лише публічний** ключ на Pi через SSH і встановіть:

```bash
sudo install -o root -g root -m 644 release-public.pem /etc/lyceumtv/release-public.pem
```

Каталог /etc/lyceumtv і всі його батьківські каталоги мають бути root-owned і недоступними програмі для запису. Довіру не можна змінювати через вебпанель.

Маніфест містить version, package_url (HTTPS), sha256 ZIP та, за бажанням, notes. Після збирання ZIP і визначення остаточних URL/хешу підпишіть JSON на довіреному комп'ютері:

```bash
.venv/bin/python tools/sign_update.py ota_manifest.json --key /private/path/release-private.pem
```

Підпис охоплює весь маніфест, крім поля signature, у канонічному JSON. Після підписування не змінюйте URL, версію, хеш чи notes. Завантажте підписаний маніфест і ZIP на HTTPS-джерело. Зміна пакета потребує нового хешу та підпису. Вбудований SHA256 залишається додатковою перевіркою цілісності.

## Kiosk Orange Pi

WebKitGTK 6.0/GTK4 працює як `lyceumtv-kiosk`, має окремий приватний профіль і штатну sandbox-модель WebKit. Режим розробника, спливаючі вікна, завантаження файлів, камера/мікрофон/геолокація відключені; верхньорівнева навігація обмежена TV/preview на loopback. Установник не вимикає AppArmor або user namespace restrictions і не додає небезпечних параметрів для обходу sandbox. При помилці WebKit перевірте журнал UID kiosk, а не запускайте браузер від root.

GTK використовує Cairo, WebKit — програмне компонування без DMA-BUF для сумісності з Mali-400/GLES2. Це не вимикає sandbox, перевірку TLS чи авторизацію. Root-owned браузерний host не оновлюється звичайним OTA; для змін системного запуску потрібен повний SSH-установник.

## Межі виконаної перевірки

Точні результати поточного релізу — reports/validation.json. Браузерні перевірки застосунку в хмарі використовують Chromium; це не перевірка фізичного Cage/WebKit на H3. Доступність ARM-пакетів перевірено за індексом Ubuntu Resolute; GI-імпорти та об’єкти налаштувань — з реальними бібліотеками GTK4/WebKitGTK 6.0 на x86_64. Повний WebKit-процес/namespace, sudo/apt/systemd/PAM на Orange Pi, Windows-установник, HDMI/звук/кодеки, firewall/SSH власника та електроживлення вимагають перевірки на пристрої.

## Runtime-права WebKit у 3.7.2

Браузер до імпорту GI перевіряє UID, встановлює no_new_privs, скидає effective/permitted/inheritable та ambient capabilities через штатні Linux API й перевіряє /proc/self/status. При невідповідності він відмовляється запускати GTK/WebKit. NoNewPrivileges у systemd збережено як додаткове обмеження. Root-owned bwrap, AppArmor, user namespace policy та sandbox не змінюються.

Standalone repair замінює лише root-owned браузерний host із точного коду релізу, зберігаючи попередній файл before-3.7.2. Відкритий service під час restart loop тепер не вважається стабільним: PID і NRestarts мають лишатися незмінними 20 секунд. Це перевірка процесу; зображення/звук ще перевіряє власник на TV.
