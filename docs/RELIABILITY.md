# Оновлення, резервні копії та відновлення

## Встановлення та конфігурація

Спочатку встановіть 3.7.0 із ZIP через PowerShell. Installer змінює ExecStart systemd на `/opt/lyceumtv/launcher.py`; просте копіювання server/ не встановлює новий supervisor. Локальний запуск: `python launcher.py`.

Перед заміною файлів installer перевіряє наявну конфігурацію. Пошкоджений JSON зберігається поряд як `config.json.invalid-*`; встановлення зупиняється. Не видаляйте config.json, якщо потрібно зберегти токени. Відновіть JSON із резервної копії або виправте його вручну. При звичайній міграції alerts_token, telegram_bot_token, медіапараметри й власні URL зберігаються; власні ключі ролей зберігаються, а відомі старі типові значення замінюються випадковими.

## OTA

Пакет має містити PACKAGE_SHA256.json, узгоджені версії server/version.py і config.example.json, необхідні runtime-файли та коректний Python. Перевіряються розміри архіву й вільне місце.

Транзакція зберігається в `data/update_jobs/<id>/`: новий код, попередні файли з хешами, окрема незмінна копія worker та результат. Supervisor зупиняє дочірній застосунок перед заміною файлів. Worker залишається живим при перезапуску застосунку, потім чекає три послідовні health-відповіді: HTTP 200, ok=true, service=LyceumTV, version=очікувана. При помилці копіювання або health — зупинка нової програми й відновлення попередніх файлів. Якщо worker перервано, supervisor виконує відновлення перед запуском застосунку.

`data/ota_pending` існує до завершення; `data/last_update.json` містить результат. Три завершені знімки зберігаються для відновлення. Live-розклади, токени й завантажені медіа не входять до заміни коду. `launcher.py` — стабільний bootstrap, який оновлює повний installer; OTA його не замінює.

Watchdog не виконує Python або інший код застосунку від root. Під час операції він надає supervisor до 180 секунд на завершення, після чого може перезапустити непривілейовану службу для відновлення. Він не видаляє маркер лише через успішний HTTP-запит. Стан і результат видно в адмінпанелі на вкладці СИСТЕМА → OTA. Після зміни backend-версії TV самостійно перезавантажує сторінку.

Ручний знімок коду: `scripts/release_snapshot.sh`. Відкат до останнього знімка: `scripts/release_rollback.sh`; дію виконує supervisor. Старі release-*.tar.gz не видаляються, але новий механізм використовує update_jobs.

## Backup

UI і systemd-таймер використовують backup_manager.py. Імена включають мікросекунди та UUID; архів стає видимим лише після повного запису. Список містить і старі daily-*.tar.gz. Зберігається налаштована кількість копій.

Якщо Pi була вимкнена у вказану годину, наступний запуск таймера після цієї години створить копію. Година 0 підтримується. Після restore застосунок перезапускається, щоб перечитати runtime-стан.

Відновлення спочатку готує всі файли. Оригінали зберігаються до завершення замін; при помилці повертаються попередні дані. Посилання й спеціальні файли TAR відхиляються.

## Офлайн та медіа

Коли /api/state повертає помилку або запит перевищує тайм-аут 5 секунд, TV може показувати останній розклад з індикатором офлайн, але післяурочне відео/музика та планова музика зупиняються. Таймер позначається як такий, що не має свіжих даних. Відомий аварійний режим візуально зберігається; нові записи звуку з кешованого стану не запускаються.

Кінцевий час показу надходить від сервера як ISO timestamp із часовим поясом. Окремий таймер зупиняє показ о 17:00 навіть під час завислого запиту API. Навіть якщо API поверне старий післяурочний стан після 17:00, показ не почнеться. Автономний передперегляд — окремий режим і працює без API.

Музика повторює спробу після помилки з паузою 1–30 секунд; зупинка/запуск скидає попередню помилку. Видалення медіазапису звільняє файл лише тоді, коли його не використовують інші записи чи налаштування. У MEDIA / SIGNAGE є «ОЧИСТИТИ НЕВИКОРИСТАНІ ФАЙЛИ»: спочатку підрахунок, потім підтвердження. Файли молодші години та .part не зачіпаються. Пошкоджені метадані зупиняють очищення.

## Межі перевірки

Регресії виконують реальні дочірні процеси, помилки копіювання, неправильну health-версію, відновлення знімка, пошкоджений JSON, restore-failure та браузерні медіасценарії. Повне встановлення через apt/systemd/Windows, фізичні HDMI/аудіовихід, апаратне вимкнення живлення та пошкодження SD-картки потребують перевірки на Pi. Програмний відкат не гарантує відновлення при фізичній несправності накопичувача.
