# 3.7.3 — сумісність GTK з Cage 0.2.1 / wlroots 0.19

- За свіжим журналом 3.7.2 capset/prctl спрацювали на ARM32: до GTK усі capability-набори нульові, NoNewPrivs=1. Нова причина перезапуску — wlr_xdg_surface_schedule_configure: Assertion surface->initialized.
- Прибрано ранній Gtk.Window.fullscreen до initial commit. Вихідний код Cage v0.2.1 не має guard у request_fullscreen; актуальний upstream його має. Cage сам позиціонує/розгортає вікно після initial commit.
- Окремий GTK/Cage headless probe використовує ту саму production-функцію показу вікна й перевіряє mapped/розмір та відсутність раннього fullscreen у Wayland trace. Це не повний ARM/WebKit/HDMI тест.
- GTK_A11Y=none за замовчуванням для неінтерактивного TV без accessibility bus.
- Додано FIX_KIOSK_ORANGEPI_373.ps1 в artifact-гілці та збережено перевірку стабільності 20 секунд, capset/prctl і захист профілю.
- Поява зображення на фізичній платі після 3.7.3 очікує підтвердження власником.

# 3.7.2 — явне скидання прав у WebKit host

- NoNewPrivileges блокує нові права, але саме по собі не скидає вже успадкований permitted-набір. Додано capset/prctl у процес браузера до GTK/WebKit з перевіркою /proc/self/status; при невідповідності запуск зупиняється.
- Окремий --check-privileges перевіряє реальні syscall/стан без GUI. До/після журнал містить лише capability-поля, без конфігурації чи ключів.
- Standalone repair атомарно замінює root-owned host, зберігає попередній файл і перевіряє 20 секунд без зміни PID/NRestarts. На помилці збирає тільки свіжі service/PAM журнали.
- Скрипти не відкривають pager. Попереднє повідомлення про успіх при одному active під час restart loop виправлено.
- Фізичний результат цього виправлення очікує перевірки власником. 3.7.1 не відновила зображення за повідомленням власника.

# 3.7.1 — виправлення WebKit kiosk на Armbian

- За журналом фізичної плати: HDMI визначається, Mali400/Lima запускається й доступний 720p; WebKit перезапускається з `bwrap: Unexpected capabilities but not setuid`.
- Kiosk отримує NoNewPrivileges=true і порожній ambient capability set. Це блокує набуття file capabilities та зберігає штатну sandbox-модель WebKit.
- Усі батьківські каталоги профілю, зокрема .cache, створюються з власником kiosk і режимом 0700. Операції через дескриптори не переходять за symlink.
- Додано окремий FIX_KIOSK_ORANGEPI.ps1 для наявного встановлення: змінює service drop-in і права каталогів, без перевстановлення пакетів/заміни даних. Backend після нього лишається 3.7.0; повний ZIP оновлює застосунок до 3.7.1.
- CHECK_ORANGEPI показує число перезапусків, налаштування й фактичні capabilities /proc та getcap, якщо він доступний.
- Фізичний результат виправлення очікує перевірки власником; сам факт active ще не доводить появу зображення.

# 3.7.0 — Orange Pi PC

- Окремий репозиторій та чистий ZIP для H3/armhf і Armbian Ubuntu/Debian.
- WebKitGTK 6.0 + GTK4 у Cage замість Chromium/Snap, GStreamer та PulseAudio для медіа.
- Перед встановленням перевіряються архітектура/ОС та GI-пакети; підтримку ARM-пакетів перевірено за індексом Ubuntu Resolute.
- Легке оформлення, обмеження пам’яті, безпечна спроба вибору доступного 720p.
- IP запитується установником і використовується в TLS та мобільному QR. Немає адреси Raspberry Pi за замовчуванням.
- Старі зовнішні джерела синхронізації вимкнено; початкові розклади/календар збережено.
- Збережено захист 3.6.1: ролі, HttpOnly-сесії, HTTPS, токени екранів, ліміти запитів/медіа, підписані OTA, окремі користувачі й root-owned службові файли.
- Актуальні результати й межі перевірки наведено в reports/validation.json.
